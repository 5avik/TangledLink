# Анимированные миры и портал TangledLink

Дата: 17 ноября 2026. Реализация в существующем клиенте, debug Playstore.
Terminal сохраняет прежние TUI, консоль, фон и кнопку.

## Интеграция и playback

- Главный путь: MainScreen → PremiumShell/HomeScreen, общий фон FloatingNavigationLayout.
  Старый MainBottomBar не вызывается главным экраном; дублирующая кнопка не добавлена.
- ui/motion/WorldMotionAssets.kt явно сопоставляет четыре ThemeId, MotionWorld,
  R.raw и существующие R.drawable. Terminal возвращает null.
- В res/raw перенесены четыре исходных MP4. SHA-256 и ffprobe совпадают с manifest:
  720×1600, 24 fps, 12 секунд, 288 кадров, H.264/yuv420p, без аудио.
  Постеры 841×1870 побайтно совпали с существующими, повторно не копировались.
  GIF/reference/sources/JSON пакета в ресурсы приложения не переносились.
- На физических устройствах используется локальный MP4 через единственный
  media3-exoplayer 1.11.1. Остальные SDK/версии/зависимости не обновлялись.
  Основа API: [официальное руководство Media3](https://developer.android.com/media/media3/exoplayer/hello-world).
- AnimatedWorldBackground.kt держит асинхронно загружаемый Coil-постер под TextureView.
  Плеер создаётся после готовности постера, поверхность становится видимой после
  onRenderedFirstFrame. Crop центрирован и сохраняет пропорции, UI остаётся сверху.
  TextureView не кликабелен, не фокусируется и скрыт от accessibility.
- Repeat ONE, volume 0, audio focus явно выключен. Нет PlayerView/controls,
  MediaSession, нового сервиса, уведомления, wakelock или разрешений для анимации.
  При смене raw, скрытии/выключении движения и dispose освобождаются плеер и surface.
  Ошибка плеера оставляет постер, не вызывает VPN-ошибку и не блокирует интерфейс.
- На AVD с hardware ranchu/goldfish выбран NativeMotionBackground из пакета.
  Причина: реальный сбой c2.goldfish.h264.decoder и высокая стоимость программного MP4
  на доступном эмуляторе. NativeWorldBackground загружает тот же постер через Coil
  и добавляет Canvas-эффекты; видео одновременно с ними не создаётся.
  Это вариант для виртуальных устройств; остальные hardware используют MP4.
- Для проверки самого MP4 на AVD Media3 предпочитает доступный software decoder.
  На физических устройствах сохраняются стандартный выбор Media3 и fallback при
  ошибке инициализации. API выбора: [DefaultRenderersFactory](https://developer.android.com/reference/androidx/media3/exoplayer/DefaultRenderersFactory).
- Из Kotlin пакета адаптированы MotionMath, Canvas-портал и NativeMotionBackground.
  Общие цвета, glow и frame clock вынесены в MotionDrawing.kt.
  Нет bitmap sequence, тяжёлого blur и декодирования изображений на каждом кадре.

## Управление движением и состоянием

- Переиспользована существующая настройка:
  «Ещё → Темы оформления → Уменьшить эффекты → Применить».
  Хранение — прежний ThemeManager/AppearanceStore и MMKV. Ключи, light/dark/system,
  dynamic color, terminal palette и default мира не изменены.
- SceneMotionPolicy.kt наблюдает lifecycle RESUMED, реальную видимость маршрута,
  ручной reduceEffects, ANIMATOR_DURATION_SCALE, PowerManager.isPowerSaveMode
  и интерактивность экрана. Есть ContentObserver, системный receiver и обновление
  при ON_RESUME. Настройки animator scale только читаются.
- При запрете движения остаётся статичная иллюстрация и законченный статичный портал.
  Frame clock не запускается; скрытый экран не продолжает декодирование.
  Превью тем статичны и не создают четыре плеера.
- ui/compose/ConnectionPortal.kt адаптирует прежний контракт к новому Canvas.
  MainUiState.isConnecting существует и выставляется текущим запросом запуска:
  используется он, а Testing/TestProgress не выдаются за Connecting.
  isRunning отображается как «VPN-сервис запущен», без обещания проверки интернета.
- Компонент поддерживает ERROR с независимыми actionLabel/statusLabel.
  В текущем MainUiState нет отдельной подтверждённой ошибки соединения, поэтому
  ошибка проверки сервера не превращается в ERROR портала. VPN-движок ради этого
  не расширялся.
- ConnectionPresentation.kt задаёт реальное представление/доступность действия.
  Существующий общий ConnectionRequestGate теперь экспортирует тот же единственный
  target как immutable StateFlow. Это наблюдаемость прежнего gate, без второго
  канала управления. Pending permission/start/stop блокирует повторную кнопку;
  отмена/ошибка используют прежний finished().
- Нажатие по-прежнему отправляет MainAction.ToggleService. Canvas, frame clock,
  lifecycle и переключение темы не отправляют VPN-действий.
  Сервисы/core/Xray/конфиги/маршрутизация/авторизация/API/платежи не менялись.

## Профилирование и ограничения

Это debug AVD с программной графикой/декодированием, не физический телефон.
Одиночные снимки разных запусков не являются сравнительным бенчмарком:

- MP4 software path: PSS 154301 KB; CPU приложения 75.8% одного ядра при работающем
  сервисе/портале. gfxinfo сообщил высокий jank и насыщенный GPU histogram;
  такие GPU-времена в этой виртуальной среде нельзя выдавать за замер телефона.
- Canvas path: PSS 126968 KB; CPU 64.2% в снимке с работающим порталом.
  Память ниже, но нагрузка всё ещё заметна; 60 FPS и низкий расход батареи
  на основании этих снимков не подтверждаются.
- После сворачивания UI-процесс показал 0.0% CPU, VPN продолжал работать.
  Это дополняет тесты остановки frame clock и освобождения session.

## Not run

- Физический Android среднего класса, аппаратный video decoder, GPU-профиль,
  длительная проверка утечек/нагрева и измерение энергии. Нельзя обещать 60 FPS.
- Покадровая проверка абсолютно бесшовного loop на физических декодерах:
  проверены повтор и ручной показ, не все кадры границы цикла.
- Реальные переключения системного animator scale 0 и Power Save не выполнялись.
  Их ветви проверены чистой политикой; системные пользовательские параметры
  анимации не менялись.
- Диалог нового VPN-разрешения и его отмена на устройстве: согласие уже было
  выдано ранее, его не отзывали ради теста. Cancel/failure gate проверен JVM-тестом.
- Точная озвучка и полный последовательный аудио-обход TalkBack: аудио устройства
  недоступно инструментам.
- End-to-end HTTP/интернет через выбранный сервер не проверялся: запуск сервиса
  и реальные счётчики не считаются доказательством интернет-доступности.
- На этапе UI-проверки использовался debug. Позднее для 0.9.8-test собран
  PlaystoreRelease с постоянной подписью; публикация описана в
  RELEASE_NOTES_0.9.8-test.md.
