# Повтор оплаты после FAILED — 15 ноября 2026

Причина обнаруженного зацикливания: MainActivity открывала сохранённый paymentUrl без новой
проверки API. Текущий live-счёт вернул FAILED через оба метода Lava; подробной причины отказа
провайдера API не возвращает. Пользователь сообщил, что списания не было.

Изменения:
- MainAction.OpenBillingPayment передаётся MainViewModel → BillingController.pay().
- Операция выполняется на IO; busy/error/snapshot остаются в StateFlow.
- POST /v1/billing/orders с orderId проверяет аккаунт из текущей bearer-сессии.
- Существующий NEW/IN_PROGRESS сохраняет ссылку. COMPLETED сверяется, новая оплата не создаётся.
- Только проверенный FAILED заменяется новым SBP-счётом для того же заказа.
- Старый ID сохраняется для сверки и позднего подтверждения; абсолютный срок заказа общий.
- SQLite claim предотвращает одновременное создание. Тайм-аут переводит в review.
- GET/возврат браузера/фоновый worker не создают новые счета.
