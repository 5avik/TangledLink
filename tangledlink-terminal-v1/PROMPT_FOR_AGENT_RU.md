## Архитектура темы и сохранение

Расширь существующий ThemeManager/ThemeConfig/repository. ID мира и terminal-палитра сохраняются отдельно; уход в другой мир сохраняет последний terminal palette. Используй фактическое хранилище проекта — в проверенном снимке MMKV. Не добавляй второй storage ради оформления. Не записывай настройки из composable.

Перенеси terminal_tokens.json в типизированный Kotlin ColorScheme для доступной версии Compose. core/TerminalPaletteTokens.kt уже содержит независимо скомпилированные terminal-цвета в ARGB Long; Color(value) адаптировать к текущей версии Compose. Не нужен JSON-парсер в runtime.

Сохрани light/dark/system и существующий dynamic color. Material-поверхности следуют текущему механизму и соответствующим схемам JSON. Терминальные панели используют свои непрозрачные paired terminal.background/surface/text независимо от dynamic color. Светлые companion-палитры — адаптации, не официальные светлые Mocha/Night/Dark. Не удаляй старые настройки и не смешивай onSurface одной схемы с background другой.

Выбор Terminal и его палитры на экране оформления поддерживает локальное preview, Apply и Cancel. До Apply не сохранять preview глобально. Back/Cancel оставляют прежний мир и палитру; Apply сохраняет согласованный итог через владельца состояния. Ошибка сохранения не должна выглядеть как успех. Неизвестный глобальный ID -> original, неизвестный terminal palette -> matrix_green. Ключи и сохранение — по ID, не ordinal.

Команда theme set меняет только terminal-палитру и применяет её сразу с сохранением, не переключая глобальный мир; она исполняется в Terminal Console. При ошибке storage оставить подтверждённую палитру и сообщить ошибку.

## Консоль: использовать готовый parser

Адаптируй core/TerminalCommandParser.kt без запуска shell. Он возвращает типизированные команды/коды ошибок; его проверки находятся в checks/TerminalCoreCheck.kt. Поддерживаемые команды и их точная семантика — COMMANDS_RU.md. Не расширяй ввод до произвольных Android/Linux-команд.

Запрещены Runtime.exec, ProcessBuilder, sh, su, root-запросы, оценка Kotlin/JS и WebView-консоль для обработки ввода. sudo — только два точных visual alias; sudo pacman -S freedom — локальная текстовая пасхалка, без установки и сети.

Реализуй TerminalCommandHandler на уровне owning ViewModel, который переводит Parsed в текущие действия/навигацию/чтение уже доступных данных. Сам parser не должен получить Context, repository, VPN-сервис или глобальный доступ к состоянию.

Connect/Disconnect обязаны быть идемпотентными. Нельзя обе команды безусловно переводить в ToggleService. Используй готовый terminalConnectionIntent как план; непосредственно перед действием перепроверь свежий isRunning и общий pending-gate. Ввод с кнопки и GUI-кнопка подключения используют один owning gate. Во время разрешения Android VPN, ожидания результата, отмены/ошибки не выполнять второй toggle. Снимать pending по фактическому результату/отмене/ошибке. Таймаут не означает Connected. Не создавай параллельное состояние VPN.

server select повторно находит актуальный GUID и отправляет существующее действие выбора; неизвестный/удалённый ID даёт локализованную ошибку. Синтаксический шаблон ID в parser при необходимости адаптируется к реальному формату проекта с тестами. Команда ping вызывает уже существующую проверку текущего сервера, без отдельного сетевого клиента или системной утилиты.

Ввод: одна строка, Enter и кнопка выполнения. История до 50 корректных команд в памяти, Up/Down и Tab/видимые подсказки, обработка экранной и внешней клавиатуры. Подсказки только из whitelist и актуальных допустимых IDs. Вывод ограничен 400 строками; длина строки также ограничена. clear очищает консоль, не удаляет VPN-файлы/данные.

Не сохраняй сырые неизвестные команды в history/logging/analytics и не отражай их в ошибке: пользователь мог вставить конфигурацию или секрет. Не записывай историю на диск по умолчанию. Сообщения об ошибках локализованы по коду, а не содержат исходный ввод. Не перехватывай фокус обычного серверного списка под консоль.

## Реальные данные, Fetch, Events и btop

Fetch показывает Android как реальную ОС, модель из доступного Android API, версию приложения и фактически доступные VPN-поля. Не выдавай телефон за Arch Linux; fastfetch/neofetch — название представления, не запущенный бинарник. Без новых опасных разрешений или root.

Events отображает безопасные доступные переходы/ошибки состояния. При входе текущее состояние отметить как снимок, не новый переход. Нет подробных событий — показывай только доступные, не придумывай handshake, DNS, сервер или timestamps прошлых событий. Открытый экран журнала может вести ограниченный in-memory буфер; не добавляй фоновый сервис для декораций.

Диагностику для копирования собирай из явного whitelist безопасных полей. Не копируй сырой logcat или конфигурацию с попыткой скрыть секреты регуляркой. Пароли, токены, приватные ключи, UUID аутентификации, raw URI и полные конфиги не выводятся. GUID выбора и credential UUID — разные сущности; не путай их.

Статистика в стиле btop использует существующие реальные download/upload/traffic/uptime/latency. Недоступный показатель — локализованное Нет данных, график пуст. Не создавай рандомные значения, вымышленные uptime и синтетические пики. Не менять engine ради отсутствующих данных. Подписки, тарифы и настройки лишь оформляются, реальные условия и значения сохраняются.
