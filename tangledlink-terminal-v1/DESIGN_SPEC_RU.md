# Terminal (Linux) — спецификация

## Характер темы

Терминальная эстетика Linux, аккуратные окна с тонкой рамкой, моноширинный текст, ASCII-пингвин, промпт `tangled@android:~$`, компактные панели. Вдохновение — терминалы, Hyprland, Fastfetch и btop; не имитация рабочего стола Linux на весь экран.

Мир имеет ID `terminal` и четыре подчинённые палитры: `matrix_green` (default), `catppuccin_mocha`, `tokyo_night`, `gruvbox_dark`. Глобальная тема по умолчанию по-прежнему Tangled Original. Сохранять ID мира и ID terminal-палитры раздельно, даже после ухода в другой мир. Не переименовывать четыре прежних ID.

## Главный экран

Сохранить фирменный знак TangledLink без tint, название, меню и текущие операции приложения. Зелёный знак одинаковый для всех миров и палитр. Добавленная палитра не является поводом менять бренд или launcher.

В connection-панели: ASCII-пингвин, реальное состояние сервиса, доступная кнопка подключения в стиле `> sudo tangledlink connect` / `> sudo tangledlink disconnect`. Слово sudo здесь — оформление и точный alias парсера, не запрос root. Системное VPN-разрешение остаётся штатным Android-процессом.

Ниже — существующий выбранный сервер и реальные доступные метрики. Не создавать ещё один серверный repository, избранное или авто-выбор, если их не было: это оформление, а не расширение VPN-возможностей. Список серверов и действия остаются доступны на маленьком экране.

Доступ к Console, Fetch и Events организовать через текущую навигацию. Отдельные пустые вкладки не добавлять. Для ширины меньше 360 dp допустимы более компактный пингвин, перенос текста и вертикальная компоновка.

Не удалять существующие light/dark/system и dynamic color. JSON содержит Material-схемы для обоих режимов; они следуют существующим настройкам, dynamic color — приоритету текущего приложения. Явные терминальные панели всегда используют согласованные непрозрачные terminal.background/surface/text; не брать onSurface из другой палитры для тёмного терминала. Это сохраняет узнаваемость выбранной схемы без сброса старых настроек.

Сетка имеет очень низкую прозрачность и остаётся декоративной. Это не обводка интерактивного контрола. Для фокуса и выбора нужна контрастная рамка/подложка. Ошибки различаются не только цветом: `[ERROR]` и текст; у Gruvbox красный — маркер, тело сообщения обычным контрастным цветом. Общий контраст рассчитывать после реального рендера, особенно при alpha.

## Шрифт и ASCII

Включён локальный JetBrains Mono Nerd Font Regular/Bold с исходной лицензией. Не использовать Nerd Font glyph как единственную подпись действия: текстовая локализованная подпись обязательна. Резерв — FontFamily.Monospace с кириллицей. Шрифт темы не должен ухудшать чтение длинных форм и сообщений.

В `ascii/` — небольшая текстовая миниатюра пингвина для оформления, а не официальный логотип Tux. Пробелы сохранять, не переносить строки. Декоративную картинку скрыть из accessibility tree; статус и действие озвучиваются отдельно. Нейтральный/idle/connected рисунок выбирается из реального UI-состояния. Не показывать Connecting, если такого достоверного источника нет.

## Console

Однострочный ввод, кнопка выполнения и Enter; ограниченный словарь команд из `COMMANDS_RU.md`. Parser выдаёт типизированное намерение. Выполнение — через владельца состояния и существующие действия. Команда theme меняет только terminal-палитру, а не глобальный мир. Изменение палитры сохраняется существующим repository; ошибка сохранения показывается без ложного успеха.

История: до 50 корректных команд на время жизни экрана/сессии. Вывод: до 400 строк, ограниченная длина строки. Сырые неизвестные команды в историю и логи не записывать: пользователь мог случайно вставить секрет. Не эхоить их в сообщении об ошибке. Не писать историю на диск по умолчанию. Подсказки берутся из whitelist, IDs серверов — из текущего списка, без утечки конфигурации.

## Fetch, Events и статистика

Fetch использует Android Build/model, версию приложения из текущего BuildConfig/PackageManager и разрешённые существующим приложением сведения. Android — реальная ОС, не Arch Linux. Не запускать fastfetch/neofetch в оболочке и не запрашивать root или новое разрешение для декораций.

Events строятся по доступным безопасным событиям состояния. Не выдавать текущее состояние в момент входа за новый переход: пометить как снимок. Если подробных событий нет, этого достаточно; не сочинять этапы handshaking. Не копировать сырой logcat: в нём могут быть токены и конфиги. Копирование диагностики строить из явного набора безопасных полей, а не из произвольного текста с попыткой замаскировать секреты регуляркой.

Статистика в стиле btop использует текущие метрики. Нет данных — пустое состояние. Не запускать отдельный ping/process/shell; команда ping использует существующую проверку выбранного сервера. График показывает только реальные отсчёты, ограниченный буфер и реальное время. Не добавлять случайные значения или синтетические пики.

## Анимация и доступность

Допустим курсор с периодом около 1000 ms, короткое плавное изменение акцента при подтверждённом переходе состояния, без полноэкранного Matrix Rain. Остановить декорации при скрытии экрана, lifecycle ниже RESUMED и уменьшении анимаций. Терминальные логи не печатать по одному символу: это мешает чтению и TalkBack.

Все клики — минимум 48 dp, семантические названия локализованы; команды могут оставаться на английском, доступное название действия — на языке UI. История и autocomplete доступны клавиатурой/D-pad. Ввод не перехватывает управление обычным списком серверов. Screen reader не должен озвучивать декоративные ASCII-строки и каждое мигание курсора.

## Состояние реализации

Этот пакет не меняет исходный Android-проект. Макеты статичны и показывают пример пустого состояния. Перенос в Compose, ViewModel/repository, реальные подписки состояния и навигация выполняются агентом по приложенному промпту.
