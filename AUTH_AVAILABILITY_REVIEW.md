# Исправление доступности входа, 16 ноября 2026

## Причина

API /health отвечал 200, но правильные данные активированного аккаунта
получали 503 panel_unavailable на /v1/login. Прямая проверка с рабочего сервера
показала CERT_HAS_EXPIRED при обращении к 3x-ui.
Публичный сертификат панели действовал до 2026-11-16 14:29:47 UTC.

Вход после проверки пароля дополнительно запрашивал панель 3x-ui.
Из-за этого истечение сертификата блокировало все аккаунты.
Автообновление ACME настроено на standalone-проверку порта 80,
который теперь занят Nginx. Расписание ACME существует (четыре раза в сутки),
но сохранённый способ проверки нужно заменить на webroot.

## Исправлено

server/server.mjs: для уже активированного локального аккаунта вход не зависит
от доступности 3x-ui. Проверка пароля, блокировка неактивированных аккаунтов,
rate limits и управление сессиями сохранены.
Первая активация, получение конфигураций и операции продления продолжают проверять
соответствующие данные панели/подписки; TLS-проверка не отключалась.

Добавлен server/auth-availability.test.mjs, включён в npm test.
Обновлён раздел границ доступа в server/README.md.
Android-код, пароли пользователей и базы аккаунтов не менялись.

## Проверено и развёрнуто

- До правки новый регрессионный тест воспроизводил 503 вместо 200.
- После правки npm test: 54 теста, 54 успешно.
- Проверены вход при недоступной панели, запрет неправильного пароля/неизвестного/
  неактивированного аккаунта, сохранение запрета доступа к конфигурации при ошибке панели,
  отказ первой активации при недоступной панели и её повтор после восстановления.
- Рабочий server.mjs до установки совпадал с Git-версией по SHA-256.
  Сохранена резервная копия на сервере; установлен проверенный файл,
  перезапущен только tngl-auth. /health снова отвечает 200.
- На Medium Phone повторный вход в предоставленный пользователем аккаунт прошёл:
  экран управления аккаунтом показывает успешную авторизацию.
  Пароль и сессионный токен в исходники/вывод диагностики не записывались.

## Обновление после первоначальной диагностики, 17 ноября

Полный restart x-ui/Xray первоначально был отклонён автоматической проверкой
из-за прерывания действующих VPN-соединений. Затем владелец обновил сертификат панели.
Для 3x-ui 3.11.0 подтверждён безопасный путь SIGHUP: он обновляет слушатели
панели/подписок, сохраняя процесс Xray. Полный restart для этой операции не использовался.

Отдельно исправлено соответствие имени сертификата подписок tngl.pro:
доменный сертификат отделён от IP-сертификата панели.
Добавлен ограниченный Certbot deploy hook server/tngl-subscription-cert-deploy.sh;
он обрабатывает только tngl.pro и посылает HUP главному процессу x-ui.
Dry run обновления доменного сертификата прошёл. Для IP-сертификата настроены
webroot /var/www/html, прежние пути установки и HUP вместо полного restart.

После восстановления TLS подтверждены успешный вход и загрузка конфигураций,
в том числе на Medium Phone. Позднее проверены запуск/остановка существующего
VPN-сервиса; его работа сама по себе не доказывает доступность интернета.

Режим webroot выбран по [официальной инструкции acme.sh](https://github.com/acmesh-official/acme.sh/wiki/How-to-issue-a-cert).
Настройка раннего продления shortlived описана в [документации профилей](https://github.com/acmesh-official/acme.sh/wiki/Profile-selection).
